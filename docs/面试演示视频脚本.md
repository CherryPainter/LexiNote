# LexiNote 项目演示视频脚本（面试 / HR 版）

> 适用场景：录屏讲解 + 口播。总时长约 4 分 30 秒。
> 使用方式：左列是「画面操作」（你在屏幕上做什么），右列的「口播台词」是你要念的话。
> 建议语速：中等偏慢，每段停顿 1 秒。全程只讲项目真实实现的功能，不夸大。

---

## 一、开场（0:00 - 0:25）

**画面：** 桌面双击 LexiNote 图标启动，展示主界面（侧边导航 + 首页）。

**口播：**

> 你好，我叫 XXX。接下来用几分钟演示一个我独立开发的项目——LexiNote，一款桌面端英语学习工具。
>
> 它完全用 Python 开发，界面用标准库 tkinter，数据用 SQLite 本地存储，可以离线使用；同时集成了本地和云端的大模型来做智能判题和内容生成。整个项目从架构设计、核心算法，到测试、打包发布，都是我一个人完成的。

---

## 二、核心功能演示（0:25 - 2:05）

**画面：** 点击侧边栏「单词学习」页，展示单词卡片、翻译、发音按钮。

**口播：**

> 先看核心功能。这是单词学习模块，展示单词、释义、例句，点这个按钮可以发音——发音用 gTTS 合成，本地做了缓存，同一个词第二次播放直接读缓存，不用重复联网。

**画面：** 切到「听写」页，输入一个单词提交，展示判对/判错反馈。

**口播：**

> 这是听写模块。我输入答案提交，系统做判定并记录结果。这里有个细节：判分不只看对错，还结合了答题的响应时间——答对时答得越快加分越多，答错时反应越慢扣分越多，让熟练度评估更接近真实掌握程度。

**画面：** 切到「复习」页，展示系统推荐的复习词。

**口播：**

> 复习模块是这个项目的核心。它不是随机抽词，而是基于遗忘曲线算法给每个词计算一个权重——综合了掌握度和距上次复习的间隔天数，越可能忘记的词权重越高，越优先被推出来复习。

**画面：** 切到「完形填空」/「阅读理解」页，点击生成一套题，展示 A/B/C/D 选项作答。

**口播：**

> 这两个是 AI 生成的题型，完形填空和阅读理解。题目由大模型根据我预置的题型规格生成，覆盖初中到考研不同难度。作答改成了 A、B、C、D 单选，直接点选，提交后自动判分并给英文解析。

**画面：** 切到「统计」页，展示学习数据图表/汇总。

**口播：**

> 最后是统计模块，把学习记录做聚合展示，方便看自己的进度。

## 三、技术架构与亮点（2:05 - 3:30）

**画面：** 切到 IDE / README，展示架构图（mermaid 三层结构图）。

**口播：**

> 讲一下技术实现。整个项目是清晰的三层架构：UI 层、业务逻辑层、数据和基础设施层，依赖自上而下，核心管理器用单例模式统一管理生命周期。

**画面：** 打开 `core/database_manager.py`，滚动到写队列相关代码。

**口播：**

> 数据层我做了几件事。数据库用 SQLite 的 WAL 模式，读写分离。写操作走一个异步写队列，由后台守护线程批量落盘，避免频繁写盘阻塞界面；需要立即拿到结果的场景再走同步提交。这样界面操作始终是流畅的。

**画面：** 打开 `core/ai_interface.py`，展示 ai_mode 相关代码。

**口播：**

> AI 这块是解耦设计。我把它抽象成三种模式：关闭、本地、云端。本地走 Ollama，云端走 OpenAI 兼容接口。三种模式互斥，关闭时完全不发网络请求。
>
> 更重要的是降级链——当 AI 不可用时，翻译、例句、判题这些功能会自动回退到本地词典和规则化处理，保证没有 AI 的情况下应用依然能用。相同的请求还做了缓存和请求合并，避免重复调用。

**画面：** 打开 `core/learning.py`，展示遗忘曲线权重公式。

**口播：**

> 刚才提到的遗忘曲线，核心就是这个权重公式，把掌握度和遗忘间隔组合起来，再做数值钳制。选词时用这个权重做加权随机采样，既优先难词，又保留一定随机性。

## 四、工程质量与发布（3:30 - 4:15）

**画面：** 终端运行 `pytest tests/ -q`，展示测试通过结果。

**口播：**

> 除了功能，我很重视工程质量。项目有完整的单元测试和集成测试，一共 300 多个用例全部通过，覆盖了核心业务逻辑、算法和各个界面页面。

**画面：** 展示 `mypy.ini` 和 `.pre-commit-config.yaml`，或运行 mypy 显示 0 错误。

**口播：**

> 静态检查用 mypy，核心模块的类型错误已经清零，并且接入了 pre-commit 门禁——每次提交自动跑类型检查，不通过就提交不了，从源头挡住类型缺陷。

**画面：** 展示 GitHub Release 页面（v2.7.1，安装包资产）。

**口播：**

> 最后是发布。我用 Nuitka 把整个应用打包成单个 exe，再用 Inno Setup 做成 Windows 安装包，带版本信息和用户协议，发布到了 GitHub Release，普通用户下载安装就能直接用。

## 附：录制小贴士

- 录屏前先把界面数据准备好（有词库、有几条学习记录），演示时不空。
- 每切换一个模块停顿一下再说话，避免画面和口播脱节。
- 技术部分（第三段）如果面向后端/Python 岗，可以讲细一点；面向前端或产品岗，可以缩短技术、多讲功能和交互。
- 如果时长要压到 3 分钟以内，删掉第三段里的代码细节，只保留架构图 + 一句话概括。
- 数字表述保持口语化，例如「三百多个测试用例」比「306 个」更自然。
